# Known limitations

- **Fixed-mode live TTS can hiccup when its producer is slower than playback.** Optional adaptive mode waits for completion when it detects a slow source before start, or after the first starvation. This bounds repeated PCM starvation but can add substantial waiting; it does not establish glitch-free output for every engine/device. Full-file URL playback hides source gaps after download. Compare actual engine, voice, text and request framing when measuring different HA routes.
- Version 0.3.1 negotiates the server's advertised streaming text protocol, matching HA's request sequence. Version 0.3.0 used plain `synthesize` even for streaming-capable engines, which can choose a different phrase-generation path. Streaming input can produce multiple audio segments; matching-format PCM segments concatenate until `synthesize-stopped`. A format change within an utterance is rejected.
- A larger queue is an upper bound, not a fixed delay. Prebuffer is measured in audio duration, not wall time. Buffering cannot indefinitely sustain output faster than synthesis. Short completed clips/tails drain below the threshold.
- Adaptive rate estimation is affected by bursts and phrase gaps; an early estimate cannot reliably predict remaining duration. Its completion fallback needs receive memory, bounded by `MAX_AUDIO_BYTES`. Consumed chunks are freed. Background remains ducked during an active recovery pause. Time/size limits can still terminate a stalled or excessive request.
- Cancel speech requires both the HA component and Rust bridge 0.5.0+. It discards speaker-side PCM/cache and closes direct/proxied TTS streams. Upstream inference cancellation requires the gateway/HA to react to disconnect. Satellite cancellation discards incoming audio through `audio-stop` while preserving the connection; no standard Wyoming cancel event is claimed.
- URL playback downloads the whole file before starting. `HTTP_DOWNLOAD_TIMEOUT_SECONDS` defaults to 120; earlier versions' 20-second limit could fail while a fresh HA TTS response was still being generated. HA caching and the satellite's assigned Assist pipeline can make apparently similar actions use different upstream work.
- One announcement item at a time; a new one replaces it. No library, playlists, HLS, DRM, internet radio or queue. URL files download completely; the cache is one private temporary file and does not survive restart/replacement. Live PCM is not seekable.
- Native output requires PipeWire; no ALSA fallback. Mono/stereo only. WAV/PCM, MP3, AAC/MP4, FLAC and Ogg/Vorbis decoders are enabled. Wyoming PCM is signed little-endian 16-bit at 8–192 kHz.
- Ducking is best effort for running controllable source streams at announcement start/resume. New streams are not automatically ducked. Shared sink/EQ/RIAA stages are excluded, but unfamiliar custom graphs may need more identification rules. Hardware playback outside PipeWire cannot be mixed/ducked.
- Original gains restore on finish, pause, stop, replacement, error, timeout and graceful SIGTERM, preserving intervening user gain changes. **A hard crash/kill or lost PipeWire connection can leave a stream attenuated.** Persistent crash recovery is not implemented.
- The shared master/mute still applies to speech. The speech slider cannot bypass a muted/quiet master. Mixed streams can clip; choose suitable gains. No bridge preamp or normalization is added.
- The HA adapter uses internal HA TTS/Wyoming APIs; currently tested on 2026.10.1. Direct mode bypasses HA file caching and output-format hints. Other engines/output modes use the URL fallback. HACS does not install/update the remote Rust service.
- MPD and HTTP are separate token-protected listeners; Wyoming is unauthenticated by its protocol. Plain HTTP/MPD do not encrypt secrets. Restrict listeners to a trusted network.
